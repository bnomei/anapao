The public entry order and complete grammar are normative:

1. required `id: <TryInto<ScenarioId> expression>;`;
2. optional title, description, tags list, typed variables expression, and metadata map;
3. required nodes and edges blocks, which may be empty so checked build owns validity;
4. optional tracked node-symbol list;
5. zero or more recursive end statements, preserving builder default when absent.

Metadata uses `key_expr => value_expr`; property/list blocks accept optional trailing commas;
declarations/scalar/end statements use semicolons. The exact queue-flow intake example must compile
unchanged.

Cover all node families, not a starter subset:

- Source, Pool, Drain, SortingGate, TriggerGate, MixedGate, Converter, Trader, Register, Delay,
  Queue, Process, Sink, Gate, and `Custom(family_expr)`;
- common `label`, `initial`, tags, and metadata;
- Pool capacity/allow-negative/mode; Drain/Sorting/Trigger/Mixed mode; Converter/Trader
  ignore-disabled/mode; Register interactive/min/max; Delay steps/mode; Queue
  capacity/release/mode;
- `mode` or trigger/action shorthand, never both;
- exclusive typed checked `config` expression for every configured family;
- optional Pool/Queue capacity and Register bounds accept a value or `none` and map to exact
  `with_*`/`without_*` methods.

Cover all transfers and edge forms:

- `fixed`, `fraction`, `remaining`, `metric_scaled`, `expression`, and typed `transfer`;
- default resource, resource block, and state block;
- exclusive typed connection expression or native resource/state fields;
- token size, role, formula, target, resource filter, enabled, and metadata;
- `node`, `resource_connection(edge)`, `state_connection(edge)`, and `formula(edge)` targets;
- pre-register all edge IDs so forward targets work.

Cover title/description/tags/typed variables/metadata, tracked node metrics, MaxSteps, metric/node
lower and upper bounds, recursive Any/All, repeated top-level ends, and typed condition
pass-through. Multiple top-level ends preserve ordered OR semantics. Do not invent threshold
scaling or a variable sublanguage.

Use only the exact predecessor APIs:

- all checked configs start from `Default` and use their field-named `with_*`; Pool/Queue capacity
  and Register min/max use exact `without_*`; positive delay/queue/resource setters accept
  `NonZeroU64`;
- all 15 `ScenarioNode` constructors plus `with_label`, `with_initial_value`, `with_tag`, and
  `with_metadata`;
- `ResourceConnection::default().with_token_size`;
- `StateConnection::default()` or `new(role, formula, target)` plus `with_role`, `with_formula`,
  `with_target`, and `with_resource_filter`;
- `ScenarioEdge::{resource,state}` plus `with_enabled` and `with_metadata`;
- `ScenarioBuilder` insertions, all scenario field/end/metric/metadata methods, and `build`.

No checked private field, independent `NodeBehavior`/`ConnectionSpec` payload construction, raw
validation, expression carrier, plan, engine, or macro-only hook is allowed.

Expansion must return `Result<Scenario, SetupError>`, use `$crate` for every Anapao path and
absolute standard paths, and bind each caller expression once before conversion/use. Derive each
node/edge ID once from exact `stringify!` spelling with fallible `new`; keep separate registries;
never use fixture IDs. Syntax misuse gets focused `anapao::scenario!:` compile diagnostics;
runtime conversion/graph failures return existing setup errors.

For declared references, clone the retained typed node/edge/metric ID. For an undeclared endpoint,
metric, tracked, state-target, or end symbol, construct the same typed `stringify!` spelling and
pass it to the checked value; `ScenarioBuilder::build` must produce its existing missing-reference
variant/path/reason/order. Do not invent macro-owned unresolved-symbol error semantics.

The emitted code may not contain macro-introduced `panic!`, `unwrap`, `expect`, `unreachable!`,
indexing, or unchecked extraction. Reserved recursive `@__anapao_*` arms stay inside the one macro;
do not export named helper macros.
