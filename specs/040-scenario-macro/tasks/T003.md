## Context

Turn `tests/scenario_macro.rs` into the complete public runtime contract. Use multiple small valid
scenarios rather than one artificial graph that violates node-family connection rules. Collectively
exercise all 15 families, every native config/common field, all typed config escape hatches, every
transfer, resource/state connection field, every state target including a forward reference, all
scenario fields, tracking, every end leaf, nested Any/All, repeated top-level ends, default end, and
typed transfer/connection/condition/variables pass-through.

Inspect through the immutable checked public accessors frozen by spec 039. Prove exact
`stringify!` symbol IDs, distinct same-spelling node/edge namespaces, declaration order where
observable, and builder duplicate semantics that retain the first definition.

Build an expression-count fixture with side effects for every category:

- scenario ID/title/description/tag/variables/metadata;
- custom family and every common/family config field class;
- transfer operands/formulas and typed transfer;
- resource/state fields, edge enabled/metadata, and typed connection;
- end values/composites/pass-through.

Each supplied expression must be evaluated exactly once. Symbols are `ident` grammar, not caller
expressions; declaration IDs are constructed once and references use retained typed values.

Prove recoverable failure/no macro-introduced unwind for:

- invalid dynamic scenario ID;
- zero Delay steps, Queue release/present capacity, and resource token size;
- missing node/edge/metric target symbols;
- duplicate node/edge symbols;
- zero fraction denominator and another whole-graph invalidity.

Assert established builder `SetupError` variants, paths, reasons, and ordering for every missing
endpoint/metric/tracked/state-target/end category; this proves registry misses flow through the
builder rather than a macro-owned unresolved-symbol error. Use unwind guards to prove the macro
does not panic; do not claim to catch a panic deliberately executed by a caller expression.

Author one representative multi-node/resource/state graph twice: once with the exact direct
`ScenarioBuilder`/checked constructors/setters and once with `scenario!`. Assert equal checked
`Scenario`s, compile both through the public checked facade, run with the same explicit seed/config,
and compare complete `RunReport`s. Reuse deterministic patterns from
`tests/checked_scenario_authoring.rs`; do not compare a reduced metric subset.

Make only narrow expansion corrections in `src/scenario_macro.rs`. Do not weaken UI diagnostics,
drop grammar, change spec-039 source, or introduce a parallel validation path.

## DoD

- Runtime tests collectively cover every family/config/common/scenario/edge/transfer/target/end
  grammar category and every typed escape hatch.
- Checked accessors prove exact IDs, namespaces, defaults, native fields, forward targets, and
  duplicate behavior.
- Side-effect counters prove one evaluation for every caller-expression category.
- Every named invalid case returns the expected setup error without macro-introduced unwind.
- Macro and direct builder produce equal checked scenarios and equal full fixed-seed reports.
- Existing checked-authoring and parity behavior remains green.
- No TODO, ignored test, abbreviated family table, or first-slice proof remains.

No Docker, network, clock, external service, or OS random seed is required.

## Escalate If

- A public accessor is missing for behavior the macro must prove; do not read private fields.
- A macro/direct checked `Scenario` or complete deterministic report differs.
- Any expression category evaluates more than once and cannot be corrected without changing the
  documented form.
- Invalid input panics or changes a checked-builder error path rather than returning it.
- A family/connection rule makes a planned test graph invalid; split it into valid focused graphs
  rather than weakening coverage.
