## Context

Replace batch's full `IndexedRunReport` transport with a private indexed compact sample produced by
the same engine transition loop. Use a private static `BatchSampleCollector`, not a second simulator
and not a public type. The sample retains only seed, completion, steps, final metrics, manifest, and
requested aggregate metric points. It must not allocate node/variable snapshots, transfer logs, or
final-node maps.

Transfer application should create/retain a `TransferRecord` only when a full-report collector wants
it or a live single-run callback must emit it. Batch emits compact summary events after report
construction and therefore does not need intermediate transfer/event storage.

Every sample is paired with `run_index`. After sequential or Rayon execution, explicitly sort by
index and fold metric/step `(sum,count)` values sequentially in that order. Do not use parallel
floating reduction. Preserve seed derivation, step averaging, run summaries, `completed_runs`,
resolved execution mode, and no-feature fallback.

Validate `AggregationConfig::Only` metrics once at batch entry against the finalized compiled plan,
before launching any run. Sample collectors consume the validated selection and must not repeat the
same lookup for every seed.

Remove the T002 interim full-report aggregation adapter and all temporary scaffolding. The surviving
code and tests use final production names only.

Required behavior includes aggregation none/final/every/all/only; mixed terminal steps; repeated
replay; complete/unique run indices; default-versus-Rayon equality; no-feature fallback; final
assertions and summary events under aggregation none; and intentional missing evidence for step or
series assertions.

Compare against T002's exact saved baselines using identical workloads and consumed checksums.
Record host/toolchain metadata, case IDs, and absolute/relative throughput and `max_bytes` deltas.
Patiently rerun noisy measurements in the same environment. No numeric performance percentage is a
spec pass/fail gate; the existing non-failing 7% Criterion summary may appear only as an optional,
descriptive flagging view. Explain repeatable regressions or evidence contradicting the
compact-allocation premise and escalate for explicit owner decision before completion. Do not
invent or silently change thresholds. Correctness and deterministic SingleThread/Rayon behavior are
hard gates and cannot be waived by a performance interpretation or owner performance decision.

## DoD

- Batch uses private compact samples and retains no discarded full-report channels.
- Sequential and Rayon samples are normalized and folded in explicit run-index order.
- Complete aggregation/final-assertion/event/fallback tests pass in default and parallel matrices.
- T002's interim adapter and any tracer/prototype flags/names/comments are removed.
- Criterion/DHAT comparisons provide complete, valid, comparable matched evidence and record exact
  results, deltas, checksums, and environment.
- Repeatable regressions or evidence contradicting the compact-allocation premise have an explicit
  recorded owner decision before acceptance.
- A fresh Sol/high validator independently reviews the collector allocation boundary, floating fold,
  and sequential/Rayon equality before acceptance.

## Escalate If

- Any implementation path changes RNG/state transitions, final metrics, event order, or public report
  fields.
- Samples cannot be made complete/unique and folded in run-index order.
- A parallel reduction or duplicated simulation loop appears necessary.
- Repeatable performance regressions or evidence contradicting the compact-allocation premise remain
  after same-environment reruns and investigation; stop for explicit owner decision.
