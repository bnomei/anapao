## Context

Perform the complete consumer/documentation repass after the final typed/compact implementation is
green. Current public examples use `CaptureConfig::none`, `final_only`, and typed periodic/selective
builders plus `AggregationConfig` for batches. No active README/rustdoc/testkit/local guidance may
recommend legacy fields or `CaptureConfig::disabled()`.

Explain four separate concepts plainly: terminal results always retained; diagnostic report
retention; live streamed events; batch aggregate sampling. Document that final assertions work with
no series, while step/monotonic/series assertions need captured/aggregated evidence. Document legacy
JSON read/current-only write behavior and the `0.2` Rust struct-literal migration.
Update `CHANGELOG.md` Unreleased only; do not bump the package version or publish the crate.

Artifact compatibility is behavioral, not a new schema: explicit no capture/aggregation produces
valid empty variable/series files where those writers are invoked, keeps manifest ownership, and
still writes supplied events/history/replay. Add focused tests rather than changing artifact file
sets.

Keep benchmark instructions aligned with exact default/parallel Criterion and isolated DHAT
save/compare commands. `testkit` fixtures preserve existing default outputs using typed constructors.

- README, CHANGELOG, and rustdoc teach the final public API and migration boundary end to end.
- Root/prelude exports and testkit examples are cohesive.
