## Context

T002 establishes `src/plan.rs`, opaque `CompiledScenario`, typed node/edge projections, and core
engine consumption. Complete the run-invariant plan in this task.

`src/validation/mod.rs` currently calls `ExprRuntime::compile` only to discard `CompiledExpr`.
`run_single_internal` then creates `EngineExpressionCache::from_compiled` and
`EngineStepPlan::from_compiled` for every run, including every batch seed.

Move these structures into compile-owned plan data:

- `CompiledExpressions` uses edge-index-aligned optional transfer and modifier-state AST slots;
- `RoutingPlan` owns resource controller/control groups, passive trigger targets, and source trigger
  outputs using `NodeIndex`/`EdgeIndex`;
- `MetricPlan` owns deterministic keys and metric-to-node resolution.

Retain the AST returned by the validation parse; do not parse twice during compilation. Delete the
per-run expression/routing constructors and borrow the retained structures during evaluation.
`ExprRuntime` itself is stateless and may remain a cheap evaluator; no lazy cache or lock is allowed.

Formula syntax/missing-AST errors become compile concerns. Runtime errors that depend on current
variables/values remain `RunError`. Preserve evaluation order, canonicalization, RNG consumption,
event order, transfer logs, reports, and sequential/Rayon determinism.

This task owns structural elimination of repeated work, not an invented wall-clock percentage.
Use existing expression fanout, gate routing, state modifier, sequential batch, and Rayon benchmark
cases as smoke/regression evidence.

## DoD

- A successful compile retains every required transfer/state `CompiledExpr` exactly once.
- Routing and metric resolution are complete immutable plan members using typed indexes.
- `EngineExpressionCache::from_compiled`, `EngineStepPlan::from_compiled`, and any replacement
  per-run plan builder are absent from run setup.
- Engine evaluation borrows retained AST/routing/metric data without a lock or clone of whole
  structures.
- Compile tests cover retained slot/group alignment and invalid formula `SetupError` behavior.
- Engine tests cover valid expression, state modifier, sorting/trigger gate, and metric behavior.
- Sequential and parallel deterministic replay tests remain equivalent.
- Criterion compile/run/expression/gate/state/batch targets compile and smoke successfully.
- Focused/full applicable gates pass, followed by fresh independent Sol/high review.

If a same-machine saved Criterion baseline exists, also run the repository
`scripts/bench-criterion` save/compare flow and attach the result without imposing a new threshold.

After commands pass, request a fresh Sol/high validator. It must confirm each AST is parsed during
compile only, no per-run plan builder remains, error timing is correct, plan data is immutable, and
deterministic behavior/evaluation order did not drift.

## Escalate If

- Retaining an expression changes error precedence or a valid runtime result.
- Routing conversion changes edge/controller iteration or RNG draw order.
- A retained component requires interior mutability to run in parallel.
- Completing the plan requires checked-authoring key/ID policy or capture-policy changes.
- Same-machine evidence shows a material regression that structural review cannot explain.
