## Context

Publish the completed checked API without removing the stable DTO route. `anapao::types` must
re-export every intended checked type, and the common prelude must include the cohesive scenario
authoring entrypoints. Add top-level re-exports only when they match the existing concise facade;
do not flood `lib.rs` with every family config.

All examples must use the exact frozen T001/T002 spellings. Do not rename constructors/setters,
introduce documentation-only aliases, or add a macro-oriented helper while writing examples.

README and crate docs must teach four complete paths:

1. load/deserialize a stable `ScenarioSpec` document;
2. check it through `Scenario::try_from`;
3. author programmatically with the complete `ScenarioBuilder` and family constructors;
4. compile through legacy `Simulator::compile` or checked `compile_checked` and run.

Document intentional 0.2 strictness: map-key/ID and explicit tag/payload mismatches now fail; the
checked builder errors on duplicates while legacy DTO helpers replace; raw JSON lexical duplicate
keys are not detected here. State that checked types are not a second serde format.

Add normal rustdoc examples and two `compile_fail` examples using
`#![deny(unused_must_use)]`, one for a checked consuming method and one for a retained DTO method.
Update `tests/readme_snippets.rs` to pin the new recommended example and use 037 read-only compiled
accessors. Examples must be feature-complete authoring/compile/run flows, not abbreviated first
slices or pseudocode.

## DoD

- Re-export paths are intentional, rustdoc-linked, and free of duplicate/conflicting names.
- README clearly distinguishes wire DTO, checked domain, builder, and compiled plan.
- A complete checked example creates multiple node families, resource/state connections, an end
  condition, tracked metric, compiles, and runs.
- Migration guidance preserves legacy usage and names every newly strict invalid case.
- Both compile-fail `must_use` examples fail for the intended lint; all normal doctests pass.
- README snippet integration tests pin checked API signatures and 037 accessor usage.
- No placeholder, tracer, MVP, TODO, or macro implementation remains in shipped docs.

## Validation

cargo fmt --all -- --check
cargo test --doc
cargo test --test readme_snippets
cargo test --test checked_scenario_authoring

## Escalate If

- Checked and DTO types create an ambiguous public re-export.
- A complete example requires private plan/validation access or a macro.
- The `must_use` compile-fail example fails for a reason other than `unused_must_use`.
- Documentation would need to promise a second serde representation.
