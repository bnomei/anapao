## Context

Build the sole public checked programmatic authoring path on T001's immutable checked values.
`ScenarioBuilder` privately owns a canonical `ScenarioSpec` draft and starts with
`ScenarioSpec::new` defaults.

Required API categories:

- `new(ScenarioId)`;
- mutation-style `insert_node` and `insert_edge` returning `Result<(), SetupError>`;
- consuming `with_node` and `with_edge` returning `Result<Self, SetupError>`;
- consuming `with_title`, `with_description`, `with_tag`, `with_variables`,
  `with_end_condition`, `with_end_conditions`, `push_end_condition`, `with_tracked_metric`, and
  `with_metadata`;
- `build(self) -> Result<Scenario, SetupError>` delegating to the T001 conversion gate.

That delegation is also the sole builder formula parse. Do not pre-validate or reparse expressions
during insertion or immediately before calling `Scenario::try_from` in `build`.

T001 freezes the exact config/node/connection/edge spellings. Do not rename or supplement them for
macro convenience. Apply `#[must_use]` to `ScenarioNode::{with_label,with_initial_value,with_tag,
with_metadata}`, `ScenarioEdge::{with_enabled,with_metadata}`,
`ResourceConnection::with_token_size`, `StateConnection::{with_role,with_formula,with_target,
with_resource_filter}`, every checked config `with_*/without_*` method, and all builder methods that
consume `self`.

Insertion derives the key from the private checked value and uses `BTreeMap::entry`. `Occupied`
returns `SetupError::InvalidParameter` at `nodes.<id>` or `edges.<id>`, leaves the first definition
unchanged, and never replaces. A mutation-style caller can handle the error and continue; the
consuming call terminates with `Err`. Do not alter the legacy replace behavior or docs of
`ScenarioSpec::with_node/with_edge`.

Mark `ScenarioBuilder` with a custom `#[must_use]` message. Mark every consuming `with_*` method on
the builder, checked node/edge/config values, and the relevant retained `NodeSpec`, `EdgeSpec`, and
`ScenarioSpec` authoring methods with custom messages. Do not expand this change to run, batch,
report, or artifact builders.

## DoD

- Both mutation-style and consuming-style complete examples build equal `Scenario`s.
- Every scenario document field has an ergonomic builder operation; no direct draft-map mutation
  escapes.
- Duplicate node and edge tests prove the first definition remains byte/field equal after a failed
  insertion.
- Legacy DTO helper tests continue to prove replacement.
- All consuming checked and scenario DTO `with_*` methods in scope carry explicit `#[must_use]`.
- Public API compile tests pin the exact T001 spellings and the already listed `ScenarioBuilder`
  signatures; no macro-only helper or private-field shortcut is added.
- Rustdoc includes one normal builder example and compile-fail coverage using
  `#![deny(unused_must_use)]` for checked and DTO discarded results.
- No typestate, derive-builder dependency, macro, or independent validation path is introduced.
- Builder build returns T001's checked `Scenario` with its private AST bundle after exactly one
  shared conversion parse; no builder-side formula cache or preliminary parse exists.

## Escalate If

- Duplicate rejection cannot leave a mutation-style builder unchanged.
- Complete metadata/variable/end-condition authoring would require public mutable fields.
- A requested `must_use` annotation changes a method signature or extends outside the scenario
  authoring surface.
- `build()` would need validation logic separate from `Scenario::try_from`.
