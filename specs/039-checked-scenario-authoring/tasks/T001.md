## Context

The existing serde declarations in `src/types/scenario.rs` are the stable document layer and must
remain unchanged in shape. Add `src/types/scenario_checked.rs` as a separate public checked domain;
declare and re-export it through `src/types/mod.rs`.

Required non-exhaustive sums are complete, not illustrative:

- `NodeBehavior`: Source, Pool, Drain, SortingGate, TriggerGate, MixedGate, Converter, Trader,
  Register, Delay, Queue, Process, Sink, Gate, and Custom;
- `ConnectionSpec`: Resource or State;
- `StateTarget`: Node or an ID-carrying ResourceConnection, StateConnection, or Formula.

Public construction spellings are frozen. Configless node constructors take `NodeId`; configured
constructors take `(NodeId, MatchingConfig)`; `custom` takes `(NodeId, impl Into<String>)`. The
constructors are exactly `ScenarioNode::{source,pool,drain,sorting_gate,trigger_gate,mixed_gate,
converter,trader,register,delay,queue,process,sink,gate,custom}`. Common node setters are exactly
`with_label(impl Into<String>)`, `with_initial_value(f64)`, `with_tag(impl Into<String>)`, and
`with_metadata(impl Into<String>, impl Into<String>)`, all returning `Self`.

Every checked config implements wire-equivalent `Default`, getters, and field-named consuming
setters. Pool uses `with_capacity(u64)/without_capacity`, `with_allow_negative_start(bool)`, and
`with_mode`; Drain/SortingGate/TriggerGate/MixedGate use `with_mode`; Converter/Trader use
`with_ignore_disabled_inputs(bool)` and `with_mode`; Register uses `with_interactive(bool)`,
`with_min_value(i64)/without_min_value`, and `with_max_value(i64)/without_max_value`; Delay uses
`with_delay_steps(NonZeroU64)` and `with_mode`; Queue uses
`with_capacity(NonZeroU64)/without_capacity`, `with_release_per_step(NonZeroU64)`, and `with_mode`.

`ResourceConnection::default()` is token size one and exposes
`with_token_size(NonZeroU64) -> Self`. `StateConnection::default()` matches the wire default;
`StateConnection::new(StateConnectionRole, impl Into<String>, StateTarget)` plus `with_role`,
`with_formula`, `with_target`, and `with_resource_filter` are the only state construction/setters.
`ScenarioEdge::{resource,state}` keep their frozen five-argument signatures and expose only common
`with_enabled(bool)` and `with_metadata(key, value)` setters. Do not add macro-only helpers.

Add immutable `Scenario`, `ScenarioNode`, and `ScenarioEdge` with private fields and read-only
accessors. Add checked config types with private fields matching every existing family DTO field.
Delay steps, queue release, present queue capacity, and resource token size use `NonZeroU64`;
other fields retain current types/defaults. Pool capacity remains `Option<u64>`.

`Scenario` retains the parsed input `ScenarioSpec`, private checked node/edge maps, and a private
crate-private `ValidatedExpressions` bundle containing deterministic
`BTreeMap<EdgeId, CompiledExpr>` transfer and modifier-state maps. Implement
`TryFrom<ScenarioSpec, Error = SetupError>` and `From<Scenario>`/`From<&Scenario>` for
`ScenarioSpec`. The whole-graph conversion is owned by `src/validation/mod.rs` and runs in this
order: node key/ID checks, edge key/ID checks, node conversion, edge/connection/target conversion,
then existing graph passes. Error order follows `BTreeMap` order.

Configured node families accept `NodeConfig::None` as their established default or their exact
variant. Configless/legacy/custom families accept only `None`. Explicit mismatch fails at
`nodes.<key>.config`. Inactive connection payloads must remain default. Node state targets forbid a
target ID; other targets require and own one. Convert established positive integers with
`NonZeroU64::new` and retain current paths/reasons. Do not add a second error taxonomy.

The shared conversion creates one `ExprRuntime`. The same parse that validates syntax must return
and retain each AST rather than mapping it to `()`. Include every resource-connection
`TransferSpec::Expression` and every modifier state formula, including disabled edges and every
state target. Exclude transfer-expression wire fields on state connections and nonmodifier
Trigger/Activator/Filter formula/control strings such as `*`; those retain their existing
blank/role/target checks. `MetricScaled`, variable-source, and end-condition variants add no AST.
The bundle has no public accessor or serde implementation. Inverse DTO projection ignores/drops it
and returns the retained parsed DTO.

## DoD

- The new checked module contains every current node/config/connection/target mapping with no
  partial completion state.
- Checked structs expose no mutable fields or mutable map access.
- Family-specific `ScenarioNode` and resource/state `ScenarioEdge` constructors bind sums to their
  payloads; no checked constructor accepts independent tag plus payload.
- Every frozen config/node/connection/edge constructor, getter, default, and setter signature is
  implemented exactly; public API tests compile those spellings and no macro-only helper exists.
- DTO-to-checked conversion preserves the parsed DTO and rejects key/ID, config, payload,
  target, and zero-value violations at stable paths.
- DTO inverse projection satisfies
  `to_value(&parsed_scenario_spec) == to_value(ScenarioSpec::from(&checked))`; tests do not compare
  against raw fixture `Value` because serde normalizes aliases/defaults before checking.
- Conversion parses every active resource-transfer and modifier-state formula exactly once and
  retains the returned AST in the private edge-ID-keyed bundle; all inactive formula-shaped fields
  are explicitly excluded and tested.
- Unit tests cover all node mappings, both connection variants, every state target, positive/zero
  conversion, inverse projection, first-error ordering, all included/excluded formula kinds,
  disabled edges, and invalid formula error paths.
- Existing valid `ScenarioSpec` validation behavior remains green.


## Escalate If

- Preserving the legacy JSON value requires changing a serde attribute, default, alias, or public
  DTO field.
- A currently valid DTO family combination cannot map uniquely to one checked variant.
- `SetupError` cannot express a deterministic path without adding a new public variant.
- The implementation would need mutable checked maps or a partial node-family set.
- A formula must be reparsed, its AST exposed publicly, or its existing error precedence changed.
