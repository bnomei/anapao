## Context

Before editing, read `specs/037-compiled-scenario-trust-boundary/tasks/T004.md` and require both
`status = "done"` and `verification_status = "passed"`. Stop if either guard is not satisfied. The
spec-level dependency plus `human_checkpoint = "before-implementation"` enforces queue ordering;
the current task-schema validator cannot encode the otherwise preferred cross-spec task edge. The
T004 contract is
normative: `src/plan.rs` owns opaque `CompiledScenario`, `ExecutionPlan`, `CompiledNode`,
`CompiledEdge`, compiled expressions, routing, and metrics; `src/validation/mod.rs` alone assembles
plans; `Simulator::compile(ScenarioSpec) -> Result<CompiledScenario, SetupError>` and
`TryFrom<ScenarioSpec>` remain; public inspection is through `scenario_id`, `source_spec`,
`node_ids`, `edge_ids`, `node_count`, and `edge_count`; raw engine/validation modules are private.

Preserve that facade and add:

- `Simulator::compile_checked(Scenario) -> Result<CompiledScenario, SetupError>`;
- `TryFrom<Scenario> for CompiledScenario` delegating to the same private assembler.

Legacy DTO compilation first obtains T001's checked `Scenario`. Plan assembly retains the canonical
source DTO for `source_spec()` while populating execution projections from checked values.
`CompiledNode` owns `NodeBehavior`. `CompiledEdge` owns `ConnectionSpec` plus 037's compiled
transfer/expression representation. Resource token size and fraction denominator are nonzero in
the relevant plan values.

T001's `Scenario` already owns the AST returned by its sole formula-validation parse. Consume the
scenario, move both edge-ID-keyed `ValidatedExpressions` maps into 037's edge-index-aligned optional
transfer/state `CompiledExpressions` slots, verify every required AST is present, and verify no
unexpected bundle entry remains. Plan assembly, `Simulator::compile_checked`, and engine setup must
not call `ExprRuntime::compile`, clone the whole AST bundle, expose `CompiledExpr`, or parse formula
text again. Inverse DTO/source-spec behavior ignores the private bundle.

The engine must branch only on checked projections. Remove wrong-family/default behavior from
`delay_steps_for_node`, `queue_release_per_step_for_node`, `node_capacity_for_node`, and
`node_mode_for_node`; remove optional-ID fallback in `trigger_targets_for_state_connection`; remove
the zero fraction branch and token-size `.max(1)`. Equivalent helpers are allowed only when their
signatures accept checked values and cannot return a repair default. Use 037 routing/index data for
referenced connections instead of revalidating DTO maps.

## DoD

- All DTO and checked compile/TryFrom entrypoints converge on one plan assembler.
- The 037 public opaque handle, accessors, source DTO contract, and private modules are unchanged.
- Plan node/edge runtime projections own checked sums and positive values.
- Every retained resource-transfer and modifier-state AST moves into the matching deterministic
  edge-index slot; no required/mismatched bundle entry remains and no formula is reparsed after
  `Scenario` construction.

  `StateConnectionTarget`; preserved DTO access is inspection-only.

  and deterministic engine tests use valid checked plans and remain green.
- Tests cover all active/inactive formula kinds, disabled edges, invalid formula error timing,
  transfer/state slot alignment, bundle exhaustion, and identical formula results through DTO and
  checked compile paths.
- A fresh Sol/high validator reviews the DTO-to-Scenario-to-plan-to-engine data flow and confirms
  no second unchecked or formula-reparse path exists.
