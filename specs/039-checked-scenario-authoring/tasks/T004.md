## Context

Add a public integration compatibility vector after the checked compile path is complete. Use the
four exact fixture files in task scope; do not generate fixtures at test runtime.

The two valid fixtures pin:

- a legacy edge with omitted default resource connection;
- a state edge using `target_edge` and `filter` aliases plus omitted `+1` formula.

The two invalid fixtures must deserialize successfully as `ScenarioSpec` but fail semantic
conversion:

- an explicit wrong-family node config;
- a node or edge map key differing from its embedded ID.

Deserialize each valid fixture to `ScenarioSpec`, then compare
`serde_json::to_value(&parsed_scenario_spec)` with
`serde_json::to_value(ScenarioSpec::from(&checked))`. Do not compare checked output with raw fixture
`Value`: `target_edge`/`filter` aliases and omitted formula/default spelling normalize during the
initial serde cycle. Exercise both `Scenario::try_from` and `Simulator::compile`; assert exact
stable error paths for invalid inputs.
Build one equivalent valid graph through mutation-style and consuming-style `ScenarioBuilder`,
compile through DTO and checked facades, run each with the same explicit seed/config, and compare
the full `RunReport`. Include resource-transfer and modifier-state expression edges so the public
DTO and checked compile paths prove identical formula validation/evaluation behavior; parse-count
and private bundle alignment remain internal T001/T003/T006 evidence.

Also pin the intentional duplicate split: checked builder insertions error and retain the first;
legacy `ScenarioSpec::with_node/with_edge` still replaces.

## DoD

- All four fixtures are human-readable, minimal, deterministic, and exercised by the integration
  test.
- Valid fixture serialization after checking equals serialization of the parsed DTO. Tests
  explicitly demonstrate that raw alias/default spelling is not the baseline.
- Invalid fixtures prove serde parsing and semantic checking remain separate phases.
- Exact map-key and config mismatch paths are asserted.
- Mutable and consuming checked builder outputs compare equal.
- DTO compile, checked compile, and both TryFrom entrypoints converge.
- Equivalent DTO/checked runs compare equal as complete reports under an explicit seed.
- Formula-bearing DTO/checked paths report identical invalid syntax paths and valid evaluation
  results for resource-transfer and modifier-state expressions.
- Tests make no network, clock, random OS seed, or service assumptions.

## Validation

```bash
cargo fmt --all -- --check
cargo test --test checked_scenario_authoring
cargo test --test readme_snippets
cargo test --all-targets
```

## Escalate If

- A valid fixture cannot preserve semantic JSON without changing a serde attribute.
- An invalid fixture fails during serde rather than checked conversion.
- Equal valid graphs produce different reports.
- Fixing a failure requires source edits outside this task's write scope; route it back to the
  owning predecessor task instead of widening scope.

## Notes

Raw repeated lexical JSON keys are intentionally not part of this compatibility vector because the
requested duplicate contract begins after a builder receives a typed node or edge.
